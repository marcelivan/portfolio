# Marcel Rivera-Baillargeon | Personal Portfolio

Public professional portfolio at https://marcelivan.github.io/portfolio/

## Intent
A business-first front door for Revenue Operations leadership, cross-functional execution, operational performance, and systems transformation. Systems architecture remains the supporting differentiator. This site is separate from private architecture and professional evidence repositories.

## Evidence and disclosure boundary
- Reference designs are original, generalized descriptions. They are **not** statements that an employer deployed, adopted, or achieved outcomes from these designs.
- No confidential employer implementations, customer or employee data, internal tickets, source code, incident descriptions, metrics, or nonpublic information.
- Public project links point only to existing public personal repositories.
- Promote specific employer work or results only after documented disclosure approval and verification.
- Avoid fabricated credentials, team sizes, certifications, financial impact, or business results.

## Publishing
Static HTML, CSS, and a minimal script. GitHub Pages serves the main branch root. No build system, cookies, third-party analytics, or form data collection.

## Maintenance
Update contact and project links only when needed. Prefer clear, durable descriptions over a recurring content-production obligation.

## Reusable executive visual system (November 2026)
- `visual-system.css` supplies responsive, semantic HTML-based flow panels and story steps, using the site's existing color tokens. No framework, dependency, tracker or image-only content was introduced.
- Homepage: `Business inputs → Revenue Operations Architecture → Unify / Automate / Govern / Measure`. Each tile is explicitly a reference capability, not a deployed or measured business result.
- Independent case: `Problem → Architecture → Intended capability → Evidence boundary`. Local observations remain separated from unverified adoption and time savings.
- Reuse these patterns when a real case is edited: one executive view first, technical detail next, and specific verified evidence last. Do not automatically convert private or company source evidence into public content.
- Verify keyboard navigation, responsive layout, contrast and evidence wording before merging; a PR or merge is not proof of GitHub Pages deployment.

## Human-readable case release checks
Every substantive visual case uses the existing executive visual vocabulary: a first-glance problem/decision/execution/evidence story, meaningful icon-led points with adjacent text, a connected diagram when it explains relationships, takeaway headings, concise readable prose and explicit verified-versus-unknown evidence. Icons must not be the only carrier of meaning. Check the heading-only story, desktop and mobile rendering, keyboard navigation, zoom/reflow and contrast before release. No new visual framework or recurring review.
