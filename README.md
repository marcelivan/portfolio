# Marcel Rivera-Baillargeon | Personal Portfolio

Public professional portfolio at https://marcelivan.github.io/portfolio/

## Intent
A business-first front door for Revenue Operations leadership, cross-functional execution, operational performance, and systems transformation. Systems architecture remains the supporting differentiator. This site is separate from private architecture and professional evidence repositories.

## Evidence and disclosure boundary
- Reference designs are original, generalized descriptions. They are **not** statements that an employer deployed, adopted, or achieved outcomes from these designs.
- No confidential employer implementations, customer or employee data, internal tickets, source code, incident descriptions, metrics, or nonpublic information.
- Public project links point only to existing public personal repositories.
- Promote specific employer work or results only after documented disclosure approval and verification.
- Avoid fabricated credentials, team sizes, certifications, financial impact, or business results.

## Publishing
Static HTML, CSS, and a minimal script. GitHub Pages serves the main branch root. No build system, cookies, third-party analytics, or form data collection.

## Maintenance
Update contact and project links only when needed. Prefer clear, durable descriptions over a recurring content-production obligation.


## Visual case-study pattern (review candidate, November 2026)
- `architecture-fitness.html` is a responsive, independent personal architecture case linked from the selected-work section.
- Design: narrative problem → lifecycle diagram → tested-versus-unknown evidence cards → clearly hypothetical capacity visualization → tradeoffs and next verification.
- Figures such as 7 hours avoided and 2.5 hours maintenance are **illustrative scenario inputs, not historical benefits, organizational ROI or observed savings**. They must not be reused as accomplishment metrics.
- No screenshot exports, employer records, private information, external analytics, new build pipeline or recurring reporting were added.
- Before publishing changes to the public portfolio, review factual claims, local test provenance, accessibility, mobile rendering and disclosure boundaries. The underlying private personal evidence remains in its authorized location.


## Connected lifecycle diagram (proposed)
The case uses four existing semantic SVG icons inside a responsive connected lifecycle diagram. On desktop the cycle forms a loop around a concise center statement; on mobile it becomes a two-column clockwise flow. The labels and full text remain native HTML, and the arrow paths are decorative for assistive technology. The footer/caption explicitly states that not all ideas should persist or cycle forever. No image export, graphic dependency, new JavaScript library or recurring design process is required. If the visual becomes less readable than the original text, simplify the diagram.
